# 30_git.md

## 1. コミット規約（物理強制）
- **形式**: `prefix: 説明`（すべて小文字、半角コロン+スペース必須）
- **許可prefix**: `fix`, `feat`, `refactor`, `docs`, `chore`, `test`, `style`, `perf`, `ci`, `build`, `revert`
- **制約**: 
    - 100文字以内を推奨。
    - 空のメッセージは禁止。
    - 日本語で記述する。
    - PRタイトルもこの形式を完全に踏襲すること。
    - commitは1つの意味ごとに分割すること。

## 2. ブランチ・Push運用
- **mainブランチ保護**: `main` への直接コミットおよび直接Pushは物理的にブロックされる。
- **ワークフロー**: 常に作業用ブランチを作成し、PR（Pull Request）経由で反映せよ。

## 3. PR（Pull Request）作成ルール
- **必須セクション**: 以下の3セクションを必ず含め、実質的な内容を記述せよ。
    1. `## Abstract`
    2. `## Changes`
    3. `## Testing`
- **機密情報検知**: PR本文およびコメント欄に、環境固有情報（ローカルパス、RFC1918 IP、同一Ownerの他リポ名）を含めてはならない。
- **PR単位**: 1つのPRは論理的にまとまった変更のみを含むこと。
- **修正量**: 1回のPRで修正するファイル数や行数は、レビュー作業の負荷を考慮して適切に制限すること。

## 4. 完了定義（DONE）
報告前に以下を自律確認せよ：
- [ ] `git diff` による意図しない変更の有無確認。
- [ ] ビルド・テストの成功。
- [ ] 改行コード（LF）、BOMなしUTF-8、末尾改行の遵守。
- [ ] `.gitleaks` によるシークレットスキャンの通過（環境にある場合）。
